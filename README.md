# DupFinder Pro

Поиск дубликатов файлов и фотографий для Windows. .NET 8 + WPF.

Приложение ищет одинаковые файлы тремя способами: точные копии (байт в байт),
одна и та же съёмка по данным камеры и визуально похожие фотографии.
Найденное показывается таблицей, лишнее отправляется в Корзину.

## Готовая сборка

Собирать ничего не нужно: в папке [`dist/`](dist/) лежит **`DupFinder.exe`** —
приложение целиком в одном файле, вместе с .NET внутри. Скачали, запустили.
Windows 10/11, 64 бита. Контрольная сумма и подробности — в [`dist/README.md`](dist/README.md).

## Как собрать самому

Нужен [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) и Windows 10/11.

```powershell
./build.ps1                    # восстановление, сборка, тесты
./build.ps1 -Coverage          # то же плюс отчёт о покрытии
./build.ps1 -Publish           # один самодостаточный exe в artifacts/win-x64
```

Запуск из исходников:

```powershell
dotnet run --project src/DupFinder.App
```

Прогон движка без интерфейса — полезно, чтобы измерить скорость на своей папке:

```powershell
dotnet run --project tools/DupFinder.Cli -- scan "D:\Фото" --min-kb 1
dotnet run --project tools/DupFinder.Cli -- gen "D:\Тест" 5000 800   # тестовый корпус
dotnet run --project tools/DupFinder.Cli -- gen-strings              # перегенерировать Strings.cs
```

Кроме `build.ps1` — тонкой обёртки над `dotnet restore/build/test/publish` — в проекте
нет ни одного скрипта: движок, приложение, тесты, генератор тестовых данных и
генератор ресурсных строк написаны на C#. Всё то же самое делается обычными
командами `dotnet`, если PowerShell не нужен.

### Как ищутся точные копии

Каждая ступень дешевле следующей и убирает большую часть кандидатов, поэтому
полностью читаются только те файлы, которые действительно могут оказаться копиями.

1. Обход папок. Симлинки и точки повторного разбора пропускаются — иначе
   ссылка на родительскую папку даёт бесконечный цикл.
2. Группировка по размеру. Файлы, размер которых больше нигде не встречается,
   отпадают, не будучи прочитанными вообще.
3. Первые 4 КБ, XxHash3.
4. Для файлов больше 1 МБ — 4 КБ из середины и последние 4 КБ. Ловит файлы
   с одинаковым заголовком и разным содержимым.
5. Полный XxHash128.
6. Подтверждение: SHA-256 или побайтовое сравнение (настройка).

Пустые файлы считаются отдельной категорией и дубликатами не признаются.

## Измеренная скорость

Замеры сделаны консольной утилитой из `tools/DupFinder.Cli`, режим «точные копии»
с подтверждением SHA-256.

| Что | Объём | Время |
|---|---|---|
| Обход и отсев по размеру | 100 000 файлов | 0,4 с |
| Полный поиск копий | 100 000 файлов, 614 МБ, 97 000 копий | 4,0 с |
| Полный поиск копий | 6 220 файлов, 2,5 ГБ, 1 185 копий | 0,95 с |
| То же, побайтовое подтверждение | 6 220 файлов, 2,5 ГБ | 0,88 с |

Оговорка: замеры сделаны в Linux-контейнере (сборочная среда), а не на
Windows с SSD, поэтому это ориентир, а не цифры из ТЗ §3. Целевой бенчмарк
«100 000 файлов / 200 ГБ на SSD» нужно повторить на рабочей машине —
для этого и сделана консольная утилита.

## Отзывчивость

ТЗ считает зависание интерфейса ошибкой уровня blocker, поэтому:

- UI-поток не читает диск, не хэширует и не декодирует картинки;
- движок целиком асинхронный, отмена срабатывает за доли секунды
  (в тестах проверяется порог 300 мс);
- прогресс приходит не чаще 10 раз в секунду;
- результаты отдаются пачками по 500 строк, коллекция таблицы уведомляет
  об изменении один раз на пачку, а не на строку;
- фильтр пересчитывается в фоне, таблица получает готовый список;
- число потоков чтения зависит от типа носителя: на HDD и в сетевой папке
  их два, на SSD — по числу ядер.

## Тесты

```powershell
dotnet test                                          # всё
dotnet test tests/DupFinder.Core.Tests               # только движок
```

Движок: 84 теста, покрытие 91,4 % строк (ТЗ требует не меньше 80 %).
Среди них приёмочные проверки из ТЗ §9 — на сгенерированном корпусе движок
находит все посаженные копии и не даёт ни одного ложного срабатывания на
файлах-ловушках (одинаковый размер с разным содержимым, одинаковое начало
с разным хвостом, файлы нулевой длины).

Тесты `DupFinder.App.Tests` и `DupFinder.Imaging.Tests` собраны под
`net8.0-windows` и выполняются только на Windows.
